# Design decisions

This log records each place where the build departs from [spec.md](spec.md), with the reason.

| Date | Spec section | Decision | Reason |
| --- | --- | --- | --- |
| 2026-10-26 | §5 (pint) | Rating functions take plain floats or numpy arrays in field units, with the unit in the parameter name. pint converts only at the input/report boundary. | The Monte Carlo layer passes vectors of 10⁵+ samples; pint wrapping at every call is slow and adds nothing inside the package. CLAUDE.md rule 4 already says pint at the boundary. |
| 2026-10-26 | §3.3, §6.1 | Ratings are returned unrounded; tests compare with published tables at ±max(0.5%, 10 psi). | The API's rounding convention is not documented in the spec, and some published values (7-in 29 lb/ft L80 collapse 7,020 psi vs. 7,025.6 computed; 7-in 26 lb/ft P110 burst 9,950 vs. 9,955.0) do not follow simple round-half-up. Rounding is a display concern only. |
| 2026-10-26 | §5 | Module layout agreed with the user (listed in CLAUDE.md). It replaces the spec's lost 8-module diagram. | The diagram did not survive export. |
| 2026-10-26 | §2.1 | Units go in the key (`kb_ft`); a value may be a unit string instead. Source notes go in a top-level `sources:` map, not on each value. | The files stay as short as the spec's example, every value still has a unit, and SI input works (needed for the §6.2 round-trip test). |
| 2026-10-26 | §2.1 example | The spec's minimal example is rejected as written: KOP 8,000 ft + 8°/100 ft build lands at 8,716 ft TVD, not 8,700. A plan takes `kop_ft` or `landing_tvd_ft`; both are allowed only if they agree within 1 ft. | An over-specified, inconsistent trajectory would silently put pressures at the wrong TVD. The tests use the example without `kop_ft`. |
| 2026-10-26 | §2.2 | A frac-gradient table cannot carry its own uncertainty block. | The spec fixes frac gradient to follow sampled pore pressure. Eaton inputs (Poisson's ratio, overburden) can be uncertain instead. |
| 2026-10-26 | §2.3 | Synthetic well (b) is tuned so `setting_depths` chooses exactly two intermediates (11,370 and 14,490 ft TVD), each with at least 0.5 ppg of kick tolerance. A test asserts this. | The spec requires (b) to need two intermediates. |
| 2026-10-26 | §2.3 | Synthetic wells corrected when design.py's new mud check flagged them. Surface-hole muds were raised to 9.1 ppg (8.6 normal pore + 0.5 trip margin). In well (c), the intermediate mud went from 9.8 to 11.0 ppg (it was below the 10.5 ppg pore pressure at its shoe), the surface shoe from 2,000 to 3,000 ft so it can tolerate the 11.0 ppg section, and the intermediate TOC from 1,500 to 2,500 ft. | The generated data must pass the program's own sanity checks. The 9.8 ppg came from WR5 and does not match this synthetic pore profile. |
| 2026-10-26 | §5 (welleng) | Minimum curvature is written in-house and tested against closed-form arcs (circle geometry, split-arc invariance, the §6.2 build), not against welleng. | welleng pulls in heavy 3D-mesh dependencies. An analytical circle is a stricter reference than another program. |
| 2026-10-26 | §2.1 | Outside a depth table the end value is held constant, and every such depth range is listed as a warning. | Linear extrapolation of the last segment can run away, for example a pore ramp extended past TD. Holding the value is predictable, and the warning makes it visible. |
| 2026-10-26 | §2.1 | An overburden table holds the average gradient Sv/TVD (psi/ft), so Sv = gradient × TVD. | This is the usual form of an overburden-gradient curve, and it shares one unit with the constant-gradient input. |
| 2026-10-26 | §5 | The deterministic run uses each distribution's base value: the mean (normal, lognormal), the midpoint (uniform) or the mode (triangular). | The spec says "base value" without defining it. |
| 2026-10-26 | §2.2 | Sampled Poisson's ratio is clipped to [0, 0.4999] before Eaton. | Eaton divides by (1 − ν); a sample at or above 0.5 has no physical meaning. |
| 2026-10-26 | §3.2 | Collapse backup (outside pressure, all collapse cases except cementing) = the mud the string was run in (Bourgoyne Ch. 7), but never less than pore pressure. | The spec defines the burst backup but not the collapse backup. Undegraded mud is the conservative textbook choice. |
| 2026-10-26 | §3.2 | Gas kick: pressure at the next section's TD = pore pressure there + kick intensity, gas column to surface. An option caps the pressure at the shoe's fracture pressure (`limit_to_shoe_frac`); it is off by default. | Off reproduces the spec §6.2 number (3,625 psi). The capped version is more realistic for some operators, but it assumes the shoe gives way first. Kick-volume models are not built yet; a given volume is noted and full gas is used. |
| 2026-10-26 | §3.2 | Lost returns with water = fracture pressure at this string's shoe, with a water column above it. Partial evacuation leaves the next section's mud below the level. Depletion = a fluid column standing on the depleted reservoir pressure at the shoe, optionally limited by an annulus level. Tubing leak = surface pressure on the packer fluid along the whole string (conservative; packer depth is not modelled). | The spec names these cases but does not define their profiles; these follow PetroWiki's internal-pressure-loads descriptions. |
| 2026-10-26 | §3.2 | Cementing uses the heaviest slurry given, from TOC to the shoe. | The fluids block has one lead and one tail density per well, with no lengths. Heaviest-everywhere is conservative. Per-string slurries would be a schema addition. |
| 2026-10-26 | §3.5 | Axial: effective tension = w × BF × (TVD_shoe − TVD), exact for any frictionless trajectory. True axial = F_eff + Pi·Ai − Pe·Ao. Service changes (ballooning, frac cooling) use MD-averaged ΔP and ΔT over the free pipe between the top and TOC, and apply only there. | The spec allows the buoyancy-factor method. Both forces are kept: true axial is needed for the triaxial check. |
| 2026-10-26 | §3.5 | Running load = installation + max(overpull, 3,200 × w shock). Overpull defaults to a 100,000 lbf placeholder. The frac fluid temperature defaults to surface temperature (maximum cooling). | The spec lists overpull and shock without values. The 3,200 × w shock factor is marked TODO(citation) until checked against Bourgoyne / Rabia. |
| 2026-10-26 | §3.1 | Kick tolerance is part of the top-down depth search, not only a check afterwards: each "choose" shoe is set no deeper than the shoe above can tolerate the required kick intensity (`gas_kick.kick_intensity_ppg`, else a 0.5 ppg placeholder). Fixed shoes are only checked. Kick tolerance uses the intensity form, with an optional gas-influx height. | Run only afterwards, the check fails by construction: top-down leaves exactly the kick margin at the shoe, and kick tolerance scales it by D_shoe/D_TD < 1. The spec's "report how often each shoe would move" implies the check can move shoes. |
| 2026-10-26 | §3.1 | Mud weights are resolved in 0.1 ppg steps (pore + trip, rounded up after rounding to 0.01), and the depth search uses the same rule. A given mud below pore + trip margin in its section is flagged. | One rule for both keeps the search and the loads consistent. Underbalanced input is a common data error. |
| 2026-10-26 | §3.4, §3.6 | Design check details. Collapse DF = biaxial rating at the case's own axial stress ÷ equivalent external pressure. Tension and compression add or subtract bending (σ_b × A_s) and use the lower of body and connection ratings. Triaxial is checked at the inner wall with bending on both sides, and skipped for collapse cases unless D/t is in the yield-collapse range. Without a manufacturer table there is no temperature derating, and the check says so. | These follow spec §3.4 and §3.6. Derating needs data the user has not supplied yet. |
| 2026-10-26 | §3.2 | The reported maximum surface treating pressure is burst-limited only. | Ballooning makes the axial and triaxial loads depend on surface pressure too. The full limit is a root-find, deferred to the probabilistic/optimizer stage. |
| 2026-10-26 | §5 outputs | The deterministic report is Markdown (`report.md`), with PNG plots and a CSV of every design-factor row. Load lines are plotted against MD, so horizontal sections are not squashed flat. | Markdown renders on GitHub and opens anywhere; the CSV is for spreadsheets. |
| 2026-10-26 | §5 output 1 | The rating lines are the nominal rating and the rating ÷ design factor. The temperature-derated line is added once a manufacturer derating table is supplied. Collapse loads are plotted as the API equivalent external pressure, the quantity the check uses. | No derating data yet; the plot should match the table. |
| 2026-10-26 | §4.4, §5 | Until the optimizer exists, the deterministic run checks a design from the input's `reference_designs`, chosen with `--design` (the first one by default). Reference sections now take `wall_in`, `drift_in` and connection ratings. Strings without a pipe get loads only. Tapered sections are not checked yet. A pipe whose drift is smaller than the next bit is flagged. | The check needs real pipe dimensions; the spec says these come from the user. |
| 2026-10-26 | §2.3 | Synthetic well (c) carries an illustrative design that uses only pipes from the spec's §6.1 table (9⅝-in 40 lb/ft L80, 7-in 26 lb/ft P110, 4½-in 11.6 lb/ft P110), so no dimensions are invented. | It gives the report a design to check. Under its 9,500 psi frac and 10,000 psi test, the 7-in fails burst, which demonstrates the spec §3.2 frac lesson. |
| 2026-10-26 | §4.1 | Only the API TR 5C3 (serviceability) resistance model is built. The ISO/TR 10400 ultimate-limit-state model (Klever–Tamano collapse, ductile-rupture burst, sampled ovality/eccentricity/residual stress, model error) waits for the standard's equations. Every reliability result says so. | CLAUDE.md rule 3: no equations reconstructed from memory. |
| 2026-10-26 | §2.2 | Pipe manufacturing variability (yield, OD and wall ratios) comes from a `pipe_statistics` input block. Missing entries use labelled placeholders that are *not from a source*: yield N(1.10, 0.05), OD N(1.00, 0.003), wall N(1.00, 0.03) truncated at 0.875. One sample of each ratio applies to the whole string, and the same statistics apply to every pipe. | Gouveia et al. (2020) Table 1 could not be read (Springer blocks automated access). The user should supply that table or the ISO/TR 10400 statistics. |
| 2026-10-26 | §4.2 | Monte Carlo uses Wilson 95% intervals (valid with zero failures) and adds 20,000-sample batches until every limit state with failures has CoV ≤ 10%, up to 10⁶ samples. FORM is improved HL-RF (Zhang & Der Kiureghian 1997) with finite differences, run on all of a string's limit states together. The reported Pf is MC when its CoV meets the target, otherwise FORM. Importance sampling at the design point is the FORM check. Correlations use a Gaussian copula. | Plain HL-RF did not converge on some limit states (min-over-nodes and regime switches). Batching keeps FORM under a second per string. MC costs about 100 µs per sample per string, about 10 s per string at 10⁵ samples; the optimizer will need FORM-first screening. |
| 2026-10-26 | §4.1 | Limit states use g = min over nodes of (rating − load), with no masking: where a load is negative, g is simply large. Sampled OD and wall change the ratings; areas for axial stress and the Lamé stresses use the nominal pipe. | Unmasked g stays smooth enough for FORM. The geometry effect on stresses is second order. |
| 2026-10-26 | §3.4 | Numerical guard on biaxial collapse: s_a/Y_p is clipped to [−2/√3, 1], and below a reduced yield of 20,000 psi (under the API formulas' range) the rating scales linearly to zero. | FORM and MC tails reach axial loads beyond yield, where the formula returns NaN. Beyond axial yield the pipe has no collapse resistance anyway. |
| 2026-10-26 | §3.1 | "How often each shoe would move" = the share of sampled pore / Poisson / overburden realizations (10,000 by default) in which the hole below a shoe can no longer reach the next shoe within the mud window or the kick tolerance. | Direct, vectorized, and it uses the same rules as the deterministic depth search. |
| 2026-10-26 | §2.1, §4.4 | The starter catalog (`catalogs/api_starter.csv`) holds only the six pipes in the spec's §6.1 table, with their published ratings; a test checks every row against the formulas. It has no drift, connection ratings or prices. Without a catalog drift, a candidate is accepted on ID against the next bit, and this is flagged (API drift is smaller than ID). | CLAUDE.md rule 2: pipe data only from a cited source. The user will supply manufacturer data sheets. |
| 2026-10-26 | §4.4 | Without prices, cost = length × weight × an illustrative grade multiplier (J55 1.0, L80 1.15, P110 1.3, ...), reported in "relative units (illustrative)" and never as dollars. If any candidate lacks a price, every candidate for that string uses relative cost. | Spec 4.4 step 3. A mix of dollars and relative units cannot be compared. |
| 2026-10-26 | §4.4 | The search is exhaustive in cost order. Every single pipe and every two-section taper (any ordered pair, crossover on a 100-ft MD grid) is checked deterministically first, and failing designs are dropped (spec 6.3). The rest are screened with FORM. The first design under the target is confirmed with Monte Carlo; if Monte Carlo disagrees, the search moves on. The §4.3 sweep comes from the same pass; choices for other targets are FORM-screened only. Strings are optimized independently. | Monte Carlo on every candidate would take hours, while FORM screening takes about 0.4 s per design. A string's loads depend only on its own pipe, so per-string optimization gives the cheapest well. |
| 2026-10-26 | §4.4 | A tapered string is evaluated node by node: two nodes 0.01 ft apart mark the crossover, so both pipes are checked there. Hanging weight sums each section's weight × ΔTVD. Ballooning and thermal forces in the free pipe use fixed-end strain compatibility, ΔF = −∫ε dL / ∫ dL/(E·A_s), which reduces to the single-pipe formulas. | It handles any number of sections, and every single-pipe result stays identical (all earlier tests unchanged). |
| 2026-10-26 | §6.3 | A reference string that costs more than 25% more or less than the optimized one is flagged. | Spec 6.3 asks for a warning on a "large gap" without defining it. |
| 2026-10-26 | §5 | `casingrel run --probabilistic` adds Pf tables, the target sweep and shoe-move odds. `casingrel optimize` chooses designs and reports them with reliability, the sweep and the reference comparison. `--max-samples` caps the adaptive Monte Carlo (default 10⁶). | Matches spec outputs 3 and 4. The tornado and Sobol charts and Pf vs treating pressure (output 5) are not built yet. |
| 2026-10-27 | §4.5, §5 | Sensitivity lives in a new `sensitivity.py`, and is computed for each string's governing limit state (highest Pf). Tornado = FORM β with one input held at its P10 and then its P90, the others random. Sobol = first-order (Saltelli 2010) and total (Jansen 1999) indices of the safety margin g, written in-house and tested against the Ishigami benchmark and an additive model, not SALib. Pf vs surface treating pressure = FORM on the frac case's limit states at 60–130% of the input pressure (a distribution's mean moves, its spread is kept); the highest pressure meeting the target is interpolated in log Pf. The CLI runs all of it with `--probabilistic` and in `optimize`; `--no-sensitivity` skips it. | The estimators are a few lines each and are checked against exact answers, so no extra dependency. The tornado and Sobol rankings can differ: Sobol measures variance of the margin, while the tornado measures the change in tail probability. |
| 2026-10-26 | §3.4 | Biaxial collapse uses the spec's formula with σ_a alone. | Open question: the standard may use (σ_a + p_i) in the axial term. Waiting on the ISO/TR 10400 excerpt before changing it. |
